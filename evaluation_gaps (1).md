## Gap 1 — RTF Capture

### Problem

SUMO prints the Real-Time Factor (RTF) to stdout at episode end in the format:

```
Step #1000; Real time 12.34s; (...)
```
or as part of the final statistics block:
```
Performance: ... Duration: 12.34s ... Real time factor: 2.45
```

This is not currently captured or stored in the results JSON. RTF is a required KPI in Chapter 3 (Table 3.3) under Computational Factors.

### Implementation

**File:** `pymarl/src/evaluate.py` (or wherever subprocess output is collected)

**Approach:** Capture SUMO stdout/stderr during each episode and parse the RTF line using regex. Store the per-episode RTF and report the mean across evaluation episodes.

```python
import re
import subprocess

# When running SUMO (or reading from libsumo stats), capture output
# RTF regex — adjust pattern to match your SUMO version's output format
RTF_PATTERN = re.compile(r"Real time factor:\s*([\d.]+)")

def extract_rtf_from_sumo_output(sumo_output: str) -> float | None:
    """Parse RTF from SUMO stdout. Returns None if not found."""
    match = RTF_PATTERN.search(sumo_output)
    if match:
        return float(match.group(1))
    return None
```

**If using libsumo**, RTF is not printed to stdout in the same way. Use wall-clock timing instead:

```python
import time

episode_start = time.perf_counter()
# ... run episode ...
episode_wall_clock = time.perf_counter() - episode_start

# RTF = simulated time / wall-clock time
# simulated time = episode_limit * step_length (e.g., 1000 steps * 1.0s = 1000s)
SIM_TIME_PER_EPISODE = env.episode_limit * env.step_length  # confirm these values
rtf = SIM_TIME_PER_EPISODE / episode_wall_clock
```

**Results JSON addition:**

```python
results = {
    # ... existing fields ...
    "mean_rtf": float(np.mean(rtf_per_episode)),
    "std_rtf": float(np.std(rtf_per_episode)),
}
```

### Verification

After implementation, run a 5-episode eval and confirm `mean_rtf` appears in the output JSON and is a plausible value (for libsumo on LOS A, expect RTF >> 1.0 given the ~9–10x speedup vs. real time).

## Gap 2 — Fuel Consumption

### Problem

SUMO's `tripinfo` output contains a `fuel` attribute per vehicle that is already being generated but not extracted by the current Python parser. Fuel consumption is a required KPI in Chapter 3 under Environmental Impact Metrics.

### Verify First

Before implementing, confirm the attribute is present in a sample tripinfo file:

```bash
grep -m 5 'fuel' path/to/tripinfo-output.xml
```

Expected output:
```xml
<tripinfo id="veh_0" ... fuel="0.823" ... />
```

If the attribute is absent, SUMO's emissions model may need to be enabled in your `.sumocfg`:

```xml
<configuration>
  <output>
    <tripinfo-output value="tripinfo-output.xml"/>
  </output>
  <processing>
    <emission-output.precision value="2"/>
  </processing>
</configuration>
```

### Implementation

**File:** Your tripinfo parser script (wherever `xml.etree.ElementTree` is used to extract KPIs)

```python
import xml.etree.ElementTree as ET
import numpy as np

def parse_tripinfo(filepath: str) -> dict:
    tree = ET.parse(filepath)
    root = tree.getroot()

    travel_times = []
    waiting_times = []
    emissions = []
    fuel_consumptions = []  # ADD THIS

    for trip in root.findall("tripinfo"):
        travel_times.append(float(trip.get("duration", 0)))
        waiting_times.append(float(trip.get("waitingTime", 0)))
        emissions.append(float(trip.get("CO2_abs", 0)))         # confirm attribute name
        fuel_consumptions.append(float(trip.get("fuel_abs", 0))) # confirm attribute name

    n = len(travel_times)
    return {
        "n_vehicles": n,
        "mean_travel_time": float(np.mean(travel_times)),
        "mean_waiting_time": float(np.mean(waiting_times)),
        "mean_co2_emissions": float(np.mean(emissions)),
        "mean_fuel_consumption": float(np.mean(fuel_consumptions)),  # ADD THIS
    }
```

> **Note:** Confirm the exact attribute names against your SUMO version. Common variants are `fuel_abs` (total fuel in ml) or `fuel` (normalized). Check one tripinfo file before hardcoding.

### Results JSON addition

Add `mean_fuel_consumption` and `std_fuel_consumption` to wherever eval results are written, alongside the existing `total_emissions` field.

## Gap 3 — Congestion Heatmap

### Problem

A congestion heatmap requires per-edge speed or density data logged over time, which is not currently being collected. Generating it requires adding a SUMO `<edgeData>` output and a post-processing visualization step.

### Scope Decision

**This gap is lower priority than Gaps 1 and 2.** The heatmap is a visualization artifact, not a quantitative KPI — the panel cannot rigorously question you on it without defined baselines for what "good" looks like spatially. Gaps 1 and 2 are quantitative KPIs explicitly listed in Chapter 3 Table 3.3 and must be filled.

**Recommendation:** Implement after full runs are complete, using saved edge-level data. If time is too tight, document it as a visualization that was considered but deferred, citing timeline constraints.

### Implementation (if in scope)

**Step 1 — Add `<edgeData>` output to SUMO config**

In your `.sumocfg` or via TraCI at episode start:

```xml
<output>
  <edgeData id="edgeDataOutput"
            file="edge_data.xml"
            freq="100"
            excludeEmpty="true"/>
</output>
```

`freq="100"` means one sample every 100 simulation seconds. Adjust based on episode length and desired resolution.

**Step 2 — Parse edge data post-episode**

```python
def parse_edge_data(filepath: str) -> dict:
    """Returns {edge_id: mean_speed} for heatmap rendering."""
    tree = ET.parse(filepath)
    root = tree.getroot()
    edge_speeds = {}
    for interval in root.findall("interval"):
        for edge in interval.findall("edge"):
            eid = edge.get("id")
            speed = edge.get("speed")
            if speed is not None:
                edge_speeds.setdefault(eid, []).append(float(speed))
    return {k: float(np.mean(v)) for k, v in edge_speeds.items()}
```

**Step 3 — Render heatmap**

Use the BGC OSM network file with `sumolib` to get edge coordinates, then render with matplotlib or folium:

```python
import sumolib
import matplotlib.pyplot as plt
import matplotlib.cm as cm

net = sumolib.net.readNet("bgc_full.net.xml")
edge_speeds = parse_edge_data("edge_data.xml")

fig, ax = plt.subplots(figsize=(12, 10))
max_speed = max(edge_speeds.values()) if edge_speeds else 1.0

for edge_id, mean_speed in edge_speeds.items():
    try:
        edge = net.getEdge(edge_id)
        shape = edge.getShape()
        xs = [p[0] for p in shape]
        ys = [p[1] for p in shape]
        # Normalize: low speed = red (congested), high speed = green (free flow)
        color = cm.RdYlGn(mean_speed / max_speed)
        ax.plot(xs, ys, color=color, linewidth=2)
    except Exception:
        continue

ax.set_title("Congestion Heatmap — Mean Edge Speed")
ax.axis("off")
plt.tight_layout()
plt.savefig("congestion_heatmap.png", dpi=150)
```
