# Feature: PopArt Path B — Full Weight Rescaling for Q_tot Target Normalisation

**Date:** 2026-04-10
**Status:** Implemented — pipeline verified, full smoke test pending
**Affected areas:** `pymarl/src/modules/mixers/qmix.py`, `pymarl/src/learners/q_learner.py`

## Context

Path A (simplified PopArt, no weight rescaling) was implemented and validated via a 50k smoke test. It failed catastrophically: `popart_std` grew to 173,810 and `popart_mean` to -1,294,570 by t=50k, and the best checkpoint reverted to the t=100 random initialisation. Path B adds the weight rescaling step that Path A omitted, directly closing the feedback loop that caused the explosion.

## Discussion and decisions

### Why Path A failed

Path A normalised TD targets and de-normalised the bootstrap term, but did not rescale the mixer's output parameters when PopArt statistics updated. This created a positive feedback loop:

1. `popart_std` grows slightly after a stat update
2. De-normalisation: `target_q_tot_denorm = target_q_tot * popart_std + popart_mean` — the larger `popart_std` amplifies the bootstrap term
3. `targets_raw` grows → `popart_std` updates to a larger value
4. Next step: even larger de-normalisation → loop repeats exponentially

The network's output remained in the old normalised scale while `popart_std` grew, so each de-normalisation step produced a larger raw value. Without rescaling the network's output layer to match the new stats, the two sides of the equation drifted apart permanently.

### Subagent investigation before Path B

Before implementing, a dedicated Explore subagent was dispatched to:
1. Map the exact output structure of `QMixer.forward()` — confirmed final output is `hidden @ w_final + v` before reshape to `(batch, 1)`
2. Verify that the TD target computation and `_update_popart()` call site were correctly identified in `q_learner.py`
3. Confirm that `GlobalQMixer` is **not** used by `q_learner.py` — it is Civiq scaffold only; `hierarchical_q_learner.py` is currently empty
4. Verify theoretical correctness of applying a fixed affine transform on top of a hypernetwork-based output — confirmed valid: PopArt rescaling is agnostic to how the output was generated; the Bellman equation is invariant to uniform linear scaling; the hypernetwork adapts to the new scale in subsequent gradient steps
5. Confirm that `output_scale` and `output_shift` as `nn.Parameter`s are automatically captured by `state_dict()`, `load_state_dict()`, `parameters()`, and `deepcopy()` — no changes needed to save/load or optimizer setup

Key finding from the subagent: the "1–2 day" original estimate for Path B was conservative. With the codebase fully mapped, the actual delta is 3 lines in `qmix.py` and ~25 lines in `q_learner.py`.

### Why output_scale / output_shift rather than rescaling an existing layer

The QMIX mixer output is dynamically generated by the hypernetwork — there is no fixed `W_out` and `b_out` to rescale as in the standard PopArt paper. The solution is to add two scalar `nn.Parameter`s (`output_scale`, `output_shift`) applied as an affine transform on top of the hypernetwork output. These are the only parameters that need explicit rescaling; the hypernetwork weights are untouched.

## What changed

### `pymarl/src/modules/mixers/qmix.py`

- `__init__`: added `self.output_scale = nn.Parameter(torch.tensor(1.0))` and `self.output_shift = nn.Parameter(torch.tensor(0.0))` — initialised to identity so behaviour is unchanged until the first PopArt stat update
- `forward()`: added `q_tot = q_tot * self.output_scale + self.output_shift` immediately before the final reshape — applies the affine transform in `(batch, 1, 1)` space before flattening to `(batch, 1)`

### `pymarl/src/learners/q_learner.py`

- New `_rescale_mixer_output(mu_old, sigma_old, mu_new, sigma_new)` method: applies the standard PopArt formula to both `self.mixer` and `self.target_mixer` using `.data.fill_()` (bypasses autograd so rescaling does not interfere with the gradient graph):
  - `scale_new = scale_old * (sigma_old / sigma_new)`
  - `shift_new = (shift_old * sigma_old + mu_old - mu_new) / sigma_new`
- `train()`: snapshots `popart_mean_old` and `popart_std_old` before calling `_update_popart()`, then immediately calls `_rescale_mixer_output()` with the old/new stats before normalising targets

## Implementation notes

`output_scale` and `output_shift` are `nn.Parameter`s, so they participate in gradient descent via Adam in addition to the explicit rescaling. This is intentional and correct — gradient descent refines the scale/shift to minimise the loss, while the explicit rescaling ensures the starting point for each gradient step is already consistent with the current PopArt distribution. The two mechanisms do not conflict.

The rescaling uses `.data.fill_()` rather than in-place tensor ops to bypass autograd. This avoids creating stale graph nodes and ensures the rescaling has no effect on the gradient computation for the current step.

`_rescale_mixer_output()` rescales both `self.mixer` (online) and `self.target_mixer`. The target mixer is also rescaled because it produces `target_q_tot` used in the bootstrap term — if only the online mixer were rescaled, the de-normalisation of `target_q_tot` would still drift.

No changes were needed to `save_models`, `load_models`, the optimizer setup, or any other file. `nn.Parameter`s are automatically handled by all of these.

## Pipeline verification (50k smoke test, seed=3)

A 50k smoke test was run immediately after implementation to verify the pipeline did not break. The test was not intended to validate the fix — 50k may be too short to observe whether `popart_std` fully stabilises — but confirms training runs without errors and produces valid outputs.

**Status:** Pipeline intact. Full validation requires a 50k–100k smoke test to confirm `popart_std` plateaus rather than exponentially grows as in the Path A failure.
