# Feature: Simplified PopArt Q_tot Target Normalisation (Mono QMIX)

**Date:** 2026-04-09  
**Superseded:** 2026-04-11  
**Status:** SUPERSEDED by Path B — do not use; kept for reference only  
**Affected areas:** `pymarl/src/learners/q_learner.py`, `pymarl/src/config/algs/qmix_sumo.yaml`

> **Path A failed its 50k smoke test.** `popart_std` exploded to 173,810 and `popart_mean` to -1,294,570 by t=50k due to a positive feedback loop from the missing weight-rescaling step. The implementation in the codebase has been replaced by Path B (full PopArt with weight rescaling), which was validated via a 500k smoke test (seed=5) on 2026-04-11. See `docs/popart_pathb_implementation.md` for the current implementation.

## Context

The 500k smoke test with reward normalisation confirmed that EMA reward-level normalisation alone does not prevent mixer divergence. Individual agent Q-values (`q_taken_mean`) stabilised at ≈-2.4 from t=200k onwards, but Q_tot targets (`target_mean`) grew to -1471 by t=500k — a 600x gap. The root cause is that reward normalisation only bounds the `r` term in the TD target; the bootstrap term `γ * Q_tot(s')` is unconstrained and amplifies through the mixer hypernetwork with every update. PopArt normalisation applied at the Q_tot level addresses this directly.

## Discussion and decisions

**Why PopArt and not gamma reduction or per-module clipping.**
Three fixes were considered:
- Reduce `gamma` to 0.9 — changes the optimization objective, makes results incomparable to standard QMIX baselines, requires a full re-evaluation. Rejected.
- Per-module gradient clipping — slows the divergence but does not address the root cause; Q_tot still accumulates through small clipped updates over many steps. Rejected.
- PopArt target normalisation — directly bounds the TD target at the level where the divergence originates (Q_tot), without changing the optimization objective or architecture. Chosen.

**Simplified PopArt (Path A) vs. full PopArt with weight rescaling (Path B).**
Full PopArt adds a weight-rescaling step that adjusts the mixer's output layer whenever the normalisation stats update, preserving the network's outputs precisely during stat shifts. For QMIX this is non-trivial because the output is dynamically generated by the hypernetwork rather than a fixed linear layer — rescaling would require either wrapping the mixer output with an additional learnable layer or only rescaling the `V(s)` sub-network. Path A (no weight rescaling) was chosen: it addresses the root cause with ~40 lines of changes to a single file, carries no architectural risk, and converges to the same equilibrium as full PopArt at the cost of slightly more variance during stat update steps. Given the thesis deadline, Path A is the right tradeoff.

**Why keep the existing reward-level EMA normalisation.**
The reward EMA (already in place from the previous smoke test cycle) provides an additional stable layer for the `r` term. Removing it in favour of PopArt alone would mean PopArt stats must absorb both reward scale and Q_tot scale from scratch. Keeping both means rewards enter the TD target already bounded, and PopArt only needs to track the additional scale introduced by the bootstrap term. The two normalisations are not in conflict.

## What changed

- `q_learner.py` — `__init__`: added `self.popart_mean = 0.0`, `self.popart_std = 1.0`, `self.popart_ema_decay` (from config, default 0.99). Initialised to identity transform so early training behaviour is unchanged.
- `q_learner.py` — new `_update_popart(targets_raw, mask)` method: EMA update of PopArt mean and std from valid (unmasked) TD targets; std floored at 1e-8 to prevent division collapse.
- `q_learner.py` — TD target block: replaced single-line `targets = rewards + γ * target_q_tot` with de-normalise → compute raw target → update PopArt stats → normalise sequence. `td_error` is now computed in PopArt normalised space.
- `q_learner.py` — logging: `target_mean` now logs the normalised target (should stay near 0 if fix works); added `popart_mean` and `popart_std` as new metrics.
- `q_learner.py` — `save_models` / `load_models`: PopArt stats persisted in `reward_stats.pth` alongside existing reward EMA stats. `load_models` uses `.get()` with defaults so checkpoints saved before this change load cleanly.
- `qmix_sumo.yaml` — added `popart_ema_decay: 0.99` under reward configuration.

## Implementation notes

The de-normalise → normalise cycle is self-stabilising: as Q_tot grows in the mixer, `popart_std` grows proportionally, and dividing by it keeps the normalised target bounded. The network learns to predict Q_tot in PopArt-normalised space; when that value is used as a bootstrap target, it is de-normalised first so the raw TD target is constructed correctly before being re-normalised for the loss. There is no double-normalisation with the reward EMA because rewards enter `targets_raw` already bounded; PopArt tracks the scale of the full target distribution including the bootstrap term.

`target_mean` in TensorBoard changes meaning with this implementation: it previously logged raw TD target values (which grew to -1471 in the smoke test) and now logs normalised values. A healthy run should show `target_mean` staying near 0. `popart_std` growing over time is expected and healthy — it is the mechanism absorbing the scale that previously caused `target_mean` to diverge.

The implementation is in `q_learner.py` only. No changes to `global_qmixer.py`, `qmix.py`, or any other module.
